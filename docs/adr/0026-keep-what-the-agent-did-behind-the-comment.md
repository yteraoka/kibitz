# エージェントの処理記録をバケットに置き、コメントにはトレーラーでリンクだけを書く

- **状態**: 採用 (2026-11-20)
- **関連**: ADR-0010 / ADR-0013 / ADR-0016 / ADR-0018 / `internal/transcript` / `docs/configuration.md`

## 背景

kibitz のコメントは結論しか書かない。「なぜこの指摘になったのか」「どのファイルを読んだのか」
「なぜ失敗したのか」を確かめるには、ワーカーのログを `event_id` で探すしかなかった。
ログには要約 (ツール呼び出しの回数、最後の発言の末尾 1,000 文字) しか残さないので、
プロンプトやツールの入出力までは追えない。

エンジンはどれも、実行中に何をしたかをイベントとして出している
(opencode / pi は JSONL、ADK はセッションのイベント)。kibitz はそれを解析して
トークン数やツールの回数を取り出したあと、捨てていた。

## 決定

**ジョブごとにエンジンの実行をすべて 1 件の記録にまとめてバケットに保存し、
投稿するコメントの末尾に `Kibitz-Transcript: <id>` のトレーラーを付ける。
kibitz-server が `/transcripts/{id}` で記録を表示し、トレーラーはそこへのリンクにする。**

- 記録はワーカーが書き、サーバーは読むだけ。同じ `KIBITZ_TRANSCRIPT_LOCATION` をそれぞれに設定する
- エンジンのイベントは**正規化せず、エンジンが出した形のまま**保存する。表示側が既知の形
  (opencode の `part`、pi の `toolName` / `message`、ADK の `content.parts`) からラベルを作り、
  知らない形は JSON のまま見せる
- トリアージ・リトライ・失敗した実行も記録する。失敗したジョブでは、エラーに id を載せて
  失敗の通知コメントにもトレーラーを付ける
- id は 128 bit の乱数。推測できないことと、PR / Issue のコメントにしか書かないことで守る。
  足りない場合のために Basic 認証のパスワード (`KIBITZ_TRANSCRIPT_TOKENS`) を任意で足せる
- 1 件あたりイベントは 16 MiB まで。保存期間はバケットのライフサイクルで決める

## 理由

### コメントに書かない

1 回のレビューのイベントは、ツールで読み返したファイルの中身を含めて数 MB になる。
コメントの上限 (GitHub は 65,536 文字) に入らないし、入っても PR が読めなくなる。
コメントには「どこを見ればよいか」だけを書く。

### トレーラーの形にする

git のトレーラーと同じ `Key: value` の 1 行にすると、レビューの本文ではなくメタデータとして読める。
機械的に拾うこともでき (`transcript.ParseTrailer`)、id だけでも運用者はバケットを直接引ける。

### 正規化しない

CLI のイベントの形はリリースごとに変わる (ADR-0024 の経緯)。kibitz の解析に合わせて削ってから保存すると、
解析が追いつかなかった版の記録ほど、肝心の部分が欠ける。生のまま持っておけば、表示を直せば昔の記録も読める。

### 誰が読めるか

記録の中身は、エージェントが読んだリポジトリのコードと、MCP サーバーが返した内容である。
リンクを PR のコメントにしか書かない以上、読める人の範囲は「コメントを読める人」になり、
非公開リポジトリならリポジトリの権限と一致する。サーバーは webhook のために公開されているので、
ログインの仕組みを持ち込むより、推測できない id を capability にするほうが単純で、範囲も変わらない。
公開リポジトリで社内ツールを MCP で読む構成のように、それでは広すぎる場合だけパスワードか IAP を足す。

### 表示はスクリプトなし

記録の中身は攻撃者が書けるもの (PR の本文や差分) を含む。html/template でエスケープし、
CSP で `default-src 'none'` にして、ページ自体が何も実行・読み込みしないようにする。

## 結果

- コメントからワンクリックで、プロンプト・ツール呼び出し・モデルの発言・エラーまで追える
- バケットの容量と、書き込み 1 回 / ジョブのコストが増える。保存期間で上限を決める
- サーバーがバケットを読む権限を持つようになる (書き込みは持たない)
- 記録の保存に失敗してもコメントは投稿する。失うのはリンクだけ
