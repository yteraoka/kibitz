# 設計文書は索引をプロンプトに載せ、本文はツールで読ませる

- **状態**: 採用 (2026-09-22)
- **関連**: PR #26 (`a67bb3a`) / `internal/worker/references.go` / ADR-0001

## 背景

**なぜそう作られたのかを知らないレビュアーは、理由が存在しないものとしてレビューする。**

ADR はずっとチェックアウトの中にあり、エージェントは読めた
(`read` / `grep` / `glob` / `rg` はすべて `allow`)。
**知る手段が無かっただけ**である。

## 決定

### 1. 索引をプロンプトに載せる

各設計文書の**パスとタイトルだけ**を 1 件 1 行で載せる。

既定のパターンは ADR の置き場所だけ:
`docs/adr/**/*.md`、`docs/decisions/**/*.md`、`adr/**/*.md`。
`KIBITZ_REFERENCE_DOCS` で変更、`off` で無効。
上限 50 件、タイトルは 90 文字。

### 2. `search_docs` と `get_doc` を `kibitz-mcp` に足す

**索引が空なら、ツールを登録しない。**

### 3. 索引は allow list でもある

索引に無いパスは拒否する。正規化して通したりはしない。

### 4. デフォルトブランチではなく**チェックアウト**から読む

## 理由

### 索引が 2 つの仕事をする

- **存在を知らせる**
- **検索語彙を渡す** — ADR は「ordering key」と書き、差分には `PublishOrdered` としか出てこない

本文を載せないのは、**30 件インライン展開すれば、情報を与えるべき差分を押しのける**から。
1 件 1 行なら、その行は働いている。

### ツールを足したのは検索能力のためではない

`rg` も `grep` も元からある。

足したのは**往復を畳むため**である。
`glob` → `read` → `read` → `read` は 4 往復で、
**1 往復ごとに会話全体がモデルに再送される**。
1 回で済むなら 1 回にする。

ついでに結果を `<<<` `>>>` で囲める。
**素の `read` の出力は囲えない**ので、これは実利である。

**索引が空のときに登録しない**のは、
「該当なし」としか答えられないツール定義を毎回送るのが、請求書の無い請求だから。

### 索引を allow list にする理由

パスは**モデルがプルリクエストを読んで組み立てるもの**である。
「文書を読む」が「任意のファイルを読む」になってはいけない。
索引に無いもの、`../` を含むもの、絶対パスは拒否する。

### チェックアウトから読む理由 (規約ファイルとの違い)

ADR-0010 の原則をそのまま適用した結果である。

| | 位置 | 取得元 |
| --- | --- | --- |
| **ADR** | **データ** (`<<<` `>>>` で囲む) | **PR 側** |
| **規約ファイル** | **指示** | **デフォルトブランチのみ** |

ADR は囲えるので、囲いが効く。だから PR 側から読んでよい。
そして PR 側から読むと、**そのプルリクエストが追加した ADR も見える**。
ADR を足すプルリクエストこそ、それに照らしてレビューする価値がある。

規約ファイルは指示の位置に入り、囲いが効かない。だからデフォルトブランチ限定のまま。

### 既定のパターンを ADR の置き場所に限る理由

`docs/**/*.md` にすると、持っているリポジトリでは索引が長くなり、
持っていないリポジトリでは無意味になる。
ADR は「X をやらないと決めた、理由はこれ」と書くもので、
これは**レビュアーに必要で、差分からは推論できない**ものそのものである。

### ツール名を名前空間なしで書く理由

プロンプトには `search_docs` / `get_doc` と書いている。
エンジンがツールをどう名前空間するかはエンジンの都合であり、
完全修飾名を埋め込むと、変わった瞬間に指示が嘘になる。
バイナリから命名規則を確定できなかったので、
**ヒントとして書き、アドレスとしては書かない**方針にした。

## 影響

- ADR を置いていないリポジトリでは、**索引もツールも出ない**。コストはゼロ。
- `docs/adr/` に置いた時点で索引に載る。設定は要らない (ADR-0001)。
- 索引は**パターンが名指しするディレクトリだけを歩く**。
  モノレポのツリー全体を横断して 3 ファイル探すのは割に合わないので。
- **参照されたかどうかを計測していない。**
  ツール呼び出しは opencode 側のイベントなので、
  `internal/reviewer/opencode/events.go` の `tool_use` を集計する形になる。
  索引の件数上限やパターンを調整する根拠として、いずれ要る。
