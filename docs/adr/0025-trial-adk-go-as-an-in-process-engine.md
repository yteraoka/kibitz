# ADK for Go を、プロセス内で動く 3 つ目の試作エンジンとして足す

- **状態**: 採用 (2026-10-13)
- **関連**: ADR-0003 / ADR-0024 / ADR-0010 / ADR-0016 / ADR-0018 / ADR-0021 / `internal/reviewer/adk` / `docs/agent-engine.md`

## 背景

OpenCode と pi は、どちらも**完成品のコーディングエージェントを子プロセスとして動かす**。
そのため kibitz は CLI の出力を解析し (`events.go`)、失敗を診断し (`diagnose.go`)、
リポジトリの設定や指示を読ませないための設定を、エンジンごとに漏れなく付けてきた。

Google の [ADK for Go](https://github.com/google/adk-go) (`google.golang.org/adk/v2`、
v2.5.0) は、エージェントループを Go のライブラリとして提供する。比べる軸が変わる。

- 何を自分で書くか (ファイル操作のツールは ADK に無い)
- 安全の境界がどこにあるか (エンジンの権限設定ではなく、kibitz のコード)

## 決定

**`KIBITZ_AGENT_ENGINE=adk` で選べる試作エンジンとして足す。既定は OpenCode のまま。**

- **モデルは Gemini (Vertex AI、ADC) に限る。** ADK には Vertex AI 上の Claude や
  Model Garden の第三者モデル向けのクライアントが無い。対応されるまでは広げない。
  起動時に `KIBITZ_MODEL` / `KIBITZ_TRIAGE_MODEL` を検査する
- **実装モードは対象外。** `KIBITZ_IMPLEMENT_ENABLED=true` との組み合わせは起動時に拒否する
- **ツールは kibitz が書く。** `read_file` / `list_dir` / `glob_files` / `grep_files` と、
  review / triage だけに渡す `write_file`。書けるのは各モードの出力ファイル 1 つだけ
- **ワークスペースの外へは `os.Root` で出さない。** パスの綴りではなく、ファイルを開く
  時点で標準ライブラリが `..`・絶対パス・外を指すシンボリックリンクを拒否する
- **MCP は ADK の `mcptoolset` (公式 Go SDK) でつなぐ。** kibitz-mcp を含め、
  local のサーバーは子プロセスのままにする。環境変数を固定リストから組み立てることも、
  egress のセッションを渡すことも、他のエンジンと同じにする
- **エージェント定義は OpenCode のものを共有する。** 本文を `InstructionProvider` で渡す
  (`Instruction` はテンプレートとして扱われ、定義の中の JSON の `{}` が壊れるため)

## 理由

### プロセス内で動くことで消えるもの

- **CLI の出力解析。** トークン数は genai の `UsageMetadata` から直接取れ、キャッシュ分と
  thinking 分も分かれている。ツールの呼び出しは ADK のイベントに、登録したときの名前のまま
  載る。エンジンの版が上がるたびに JSON の形を追いかける必要が無い
- **リポジトリの設定・指示を読ませないためのフラグ。** ADK は `AGENTS.md` も skill も
  設定ファイルも読まない。OpenCode の `OPENCODE_DISABLE_PROJECT_CONFIG` や pi の
  `--no-context-files` のような、**止め忘れうるスイッチ自体が存在しない** (ADR-0010)
- **シェル。** 渡していないツールはモデルから呼べない。権限設定で `deny` にするのではなく、
  そもそも存在しない

### 代わりに引き受けるもの

- **安全の境界が worker のプロセスの中に移る。** 他のエンジンでは、エージェントのプロセスに
  渡す環境変数を絞ることが最後の砦だった。ADK ではツールが GitHub App の鍵を持つプロセスの
  中で動く。だからパスの検査を綴りの比較ではなく `os.Root` に任せ、テストで `..`・
  シンボリックリンク・書き込み先を確かめている
- **ツールの作り込み。** 出力の切り詰め、バイナリの扱い、`.git` の除外などを自分で持つ。
  OpenCode のツールの説明文やシステムプロンプトの調整は引き継げないので、**レビューの質は
  比較して確かめる必要がある**
- **ADK の上流の変化。** v1 から v2 で破壊的変更があり、OpenAI 向けのクライアントは
  experimental。Renovate で追いかけるたびに費用がかかる

### モデルの通信は egress のプロキシを通さない

ADR-0021 のプロキシは、言いくるめられたエージェントが**どこへ行けるか**を絞るためのもの。
モデルの宛先はエージェントが選ぶものではなく、設定で決まった worker 自身の通信で、
資格情報もエージェントには見えない。OpenCode ではたまたまエージェントのプロセスから
出ていたのでプロキシを通っていたが、ADK では通さない。remote の MCP サーバーへの通信は
ジョブの `http.Client` にセッションを設定し、local のサーバーには環境変数で渡す。

## 試作で確かめること

| # | 確かめること | 状況 |
| --- | --- | --- |
| 1 | kibitz-mcp (自前の最小実装) と公式 Go SDK のクライアントが通じるか | **確認済み。** 実プロセスでの結合テスト `TestRunWithKibitzMCP` |
| 2 | ワークスペースの外を読めず、出力ファイル以外に書けないか | **確認済み。** 台本どおりに応答する偽モデルで `..`・外を指すリンク・`main.go` への書き込みが拒否される |
| 3 | 実際の Gemini で、OpenCode と同じ PR に同等の質のレビューが返るか | **未確認。** 同じ PR の集合で、指摘・トークン・所要時間・ツールの使われかたを比べる |
| 4 | Vertex AI の暗黙のキャッシュが効くか (`CachedContentTokenCount`) | **未確認** |
| 5 | 第三者製の remote MCP が egress のセッション越しに使えるか | **未確認。** OAuth を要るサーバーは未対応で、警告を出して外す |

## 結果

- `internal/reviewer/adk` が増えた。テスト込みで約 2,100 行で、OpenCode のエンジン (同じく約 3,700 行) より小さい
- worker のイメージにある opencode のバイナリは、adk を選んでも使われないだけで残る。
  外すのは比較が終わって判断してから
- セッションはコンテナのメモリにあり、件数の上限 (200) を超えたら古いものから捨てる。
  ADK の `session.Service` を Firestore で実装すれば、コンテナが消えても会話を続けられる
  (worker.md §7 の「セッションはあれば得をするもの」を変えられる) が、試作の範囲外とした
