# レビュー範囲を絞り、かかった費用をレビュー本文に書く

- **状態**: 採用 (2026-09-22)
- **関連**: PR #8 / PR #9 / PR #14 / PR #17 / `docs/worker.md`

## 背景

AI レビューは 1 回あたりの単価がある。
そして**同じ差分を何度も読み直す**構造になりやすい。

- 2 回目のレビューが、**プルリクエスト全体をもう一度読んでいた**。
  同じ 100 行、同じ指摘、同じ請求。
- 10 万行の差分はプロンプトに入らない。
  そしてそれが分かるのは、**1 回分の実行を使い切ったあと**である。

さらに、費用が見える場所にも問題があった。
トークン数はメトリクスとログにあったが、
**このボットを続ける価値があるかを判断する人は、コメントを読む人**である。
その人には見えていなかった。

## 決定

**読む量を 3 つの方法で絞り、結果として何を使ったかをレビュー本文に書く。**

### 1. インクリメンタルレビュー

最後にレビューしたコミットと現在の head を比較し、**差分の差分だけ**を読む。

ただし**指摘の検証は差分全体に対して行う**。
読む範囲を狭めることが、コメントしてよい範囲を広げてはいけないので、
プロンプトのスコープと投稿可能な位置は分けて持つ。

### 2. トリアージ

差分が `KIBITZ_MAX_DIFF_LINES` を超えたら、先に**ファイル一覧だけを読む**パスを走らせ、
どれを読む価値があるかを選ばせる。**トリアージのプロンプトには patch を載せない。**
差分を読むパスは、節約しようとしているものをそのまま使ってしまう。
`KIBITZ_TRIAGE_MODEL` で安いモデルを充てる。

差分に無いパスは、信用せずに無視する。
**何を読むかを選ぶことが、何を読めるかを広げてはいけない。**

### 3. コメント数の上限

`KIBITZ_MAX_COMMENTS` (既定 20)。超えたら深刻度の高いものを残す。

### そして費用を本文に書く

```
レビュー対象: `3f7a1c2` / 所要 1m58s
トークン: 入力 123,456 / 出力 7,890 / 概算 $0.233
```

## 理由

### 絞り方すべてに、絞れないときのフォールバックがある

**読みすぎはコストだが、読まなすぎはバグの見逃しである。** 後者のほうが高い。

だから絞れない経路はすべて差分全体に落ちる。
前回のレビューが無い、`--full` が付いている、forge が比較に答えられない、
比較結果が空、トリアージが失敗した、何も選ばなかった、
選んだものが差分に無い — 全部フォールバックする。

force push や rebase は古いコミットを持ち去るので GitHub は 404 を返す。
これは `forge.ErrNoCompare` で、**失敗ではなく普通の出来事**として扱う。

### 絞ったことを黙らない

サマリに「レビュー対象: `abc1234..def5678`」と書く。
これは**短いレビューと壊れたレビューの違い**である。
トリアージが絞ったときは、**読まなかったファイルを名指しする**。
半分を黙って飛ばしたレビューは、レビューが無いより悪い。

### 金額について推測しない

kibitz は**モデルの値段を知らないし、知っているふりをしない**。
価格はプロバイダ・リージョン・契約で変わり、しかも変動する。
誰も入力していない数字は、誰も信用すべきでない数字である。

だから `KIBITZ_MODEL_PRICES` を設定する (100 万トークンあたり `model=input/output`、
`*` でフォールバック)。**何も設定されていなければ、トークン数だけを出して金額には触れない。**
何も言わないことは、ゼロと言うことと同じではない。

見積もりは**上限**であり、そう表示する。

## 影響

- `Usage.Add` があるのは、トリアージを使ったレビューが**2 回トークンを使う**ため。
- **トークン数が 0 のまま出ていた時期がある** (PR #17)。
  `opencode run --format json` は 1 行 1 オブジェクトで、
  トークンは **`step_finish` の `part.tokens` にしか無い**。
  しかも**ステップごと**なので合算が要る。
  当初のパーサは `usage` / `inputTokens` / `prompt_tokens` といった
  推測したキー名を見ており、どれにも当たっていなかった。
  出荷済みバイナリを読んで確定した。
  - `input` はキャッシュが供給した分を**含まない**
  - `output` は reasoning を**含まない**
  - だから足し合わせずに、エージェントが報告したまま保持する
- 同じ修正で、**reasoning のテキストがレビュー本文に混ざる**問題も直った。
  `textFrom` が `text` 以外の part を読み飛ばすようにしてある。
- 通貨記号は価格設定に従う。
