# コメントで依頼できる人を運用側で絞り、断ったことはリアクションで伝える

- **状態**: 採用 (2026-09-30)
- **関連**: `internal/policy` / `internal/webhook/react.go` / `docs/configuration.md` の「コメントで依頼できる人」 / ADR-0012 / ADR-0020

## 背景

kibitz 宛てのコメント (`/kibitz review` など) は、書いた人が誰であっても
ワーカーを起こしてモデルを呼んでいた。public リポジトリでは誰でもコメントを
書けるので、**誰でもレビューを起こし、その費用を運用者に払わせられる**。

ADR-0012 はボットが動く条件をイベントの種類とメンションで絞ったが、
**誰が**言ったかは見ていなかった。

## 決定

**運用側の許可リスト (`KIBITZ_ALLOWED_COMMENTERS`) に無い人のコメントは、
サーバーでキューに載せずに捨てる。捨てたことは、そのコメントへの
リアクションで伝える。**

- 対象は kibitz 宛てのコメントだけ。宛てていないコメントには何もしない
- 見るのはコメントを書いた人の login。`github:alice` でプラットフォームを限れる
- 未設定なら従来どおり誰でも依頼できる
- リアクションは GitHub が 👎 (`-1`)、GitLab が 🚫 (`no_entry_sign`)。
  Azure DevOps には付けない

## 理由

### サーバーで判定する

ワーカーで判定すると、断る依頼のためにもワーカーが 0 台から起動する。
誰が書いたかはペイロードにあり、リポジトリの設定を読む必要も無いので、
キューに載せる前に決められる。ADR-0012 の判定と同じ場所に置く。

### 断ったことを伝える

他のスキップ (メンションが無い、キーワードが無い) は、誰も返事を待っていない。
これは違う。**依頼した人が返事を待っている**。何も起きなければ、
kibitz が壊れているように見える。

### 返信ではなくリアクションにする

「あなたには権限がありません」と返信する案は捨てた。返信にすると、
**誰でも kibitz にコメントを書かせられる**。それは許可リストが防ごうとしている
ことの一種で、スレッドを埋める道具にもなる。リアクションは同じ人が何度頼んでも
1 つのままで、既存の資格情報 (ADR-0020) で付けられる。

### Azure DevOps には付けない

Azure DevOps の PR コメントに付けられるのは like だけで、断ったことを表せない。
like を付ければ逆の意味になるので、何も付けない。ログには残る。

### リポジトリ側からは広げられない

許可リストは運用側の設定で、`.kibitz.yaml` からは変えられない。誰が依頼できるかを
リポジトリの中に書けば、それを書き換える PR で自分を足せてしまう (ADR-0011 と同じ判断)。

### PR の作成と push は対象外にする

それは誰かが依頼したものではない。自動レビューを絞る手段はすでにある
(`KIBITZ_TRIGGER_KEYWORDS`、`.kibitz.yaml` の `triggers`)。

## 影響

- `forge.Reactor.React` がリアクションの種類 (`seen` / `refused`) を受け取るようになった
- `kibitz_reactions_total` に `kind` ラベルが増え、`outcome` に `unsupported` が増えた
- 断った配送は `reason=actor_not_allowed` と `author` 付きでログに出て、
  `kibitz_webhooks_received_total{outcome="skipped",reason="actor_not_allowed"}` で数えられる
- login は変更でき、手放された名前は他人が取得できる。リストは定期的に見直す
