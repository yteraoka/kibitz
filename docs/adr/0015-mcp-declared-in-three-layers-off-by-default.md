# MCP は三層で宣言し、既定では何も有効にしない

- **状態**: 採用 (2026-09-22)
- **関連**: PR #22 (`df2f165`, `3f12730`) / `docs/configuration.md` / `docs/security.md`

## 背景

Phase 7 の目的は「プルリクエストが参照しているチケットを引けるレビュー」である。
そのためには Jira や Sentry のような**第三者が提供する MCP サーバー**に繋ぐ必要がある
(それが OpenCode を選んだ理由でもある — ADR-0003)。

だが MCP サーバーは資格情報を持つ。そして
**ローカル MCP サーバーは、kibitz が書いていないバイナリを opencode が起動したもの**である。

## 決定

### 1. 三層で宣言する

| 層 | 設定 | 決めること |
| --- | --- | --- |
| デプロイ | `KIBITZ_MCP_SERVERS` | **何が存在するか** (名前 → サーバー定義の JSON) |
| デプロイ | `KIBITZ_MCP_ALLOWLIST` | **リポジトリが要求してよいものはどれか** |
| リポジトリ | `.kibitz.yaml` の `mcp.allow` | **実際に何を使うか** |

**リポジトリが要求しない限り、何も有効にならない。**

### 2. 資格情報は config に書かない

サーバー定義の中には `{env:NAME}` と書く。
opencode が自分のプロセス環境から置換する
(1.18.31 に対して検証済み。`headers` と `environment` の中でも効く)。
**kibitz が書き出す config ファイルには、プレースホルダしか入らない。**

### 3. エージェントのプロセス環境を作り直す

worker の環境をそのまま渡すのをやめ、**リストから組み立てる**。

- どんなプログラムにも要るもの (PATH、HOME、プロキシ、CA、ADC)
- 設定されたプロバイダの資格情報
- **このジョブで有効なサーバーが参照している変数だけ**

### 4. fork のプルリクエストでは既定で無効

`AllowFork` が明示されているサーバーだけが、fork からのプルリクエストで動く。

### 5. トリアージには一切渡さない

## 理由

### 「使えるだけ」でも課金される

ツール定義は**リクエストのたびに送られ、モデルが呼ぶかどうかに関係なくトークンを食う**。
有効にしただけのサーバーは、誰も同意していない請求書である。
だからオプトイン。トリアージがファイル名しか読まないのと同じ理由で、
トリアージには渡さない。

### エージェントの環境に何が入っていたか

この見直しの出発点は、**渡していたものが worker の持ち物全部**だったことである。
webhook secret、GitHub App の秘密鍵、GitLab のトークン。

opencode が唯一の子プロセスだった間は、まだ耐えられた。
**いまは耐えられない。** ローカル MCP サーバーは kibitz が書いていないバイナリで、
opencode が起動し、opencode の環境を継承する。

いまは、jira を有効にしたジョブは `JIRA_TOKEN` を得て、
sentry だけを有効にしたジョブは得ない。
`KIBITZ_AGENT_ENV_PASSTHROUGH` が逃げ道で、
「全部継承する」に戻すよりはこちらのほうがよい。

### 設定の食い違いは、誰が見るべきかで扱いを変える

- **リポジトリが、このデプロイに無いサーバーを名指しした**
  → ログとサマリコメントで伝える。
  **何かを頼んで何も起きないことが、何も頼まないことと同じに見えてはいけない。**
- **デプロイの 2 つの設定が食い違っている** (定義はあるが allowlist に無い)
  → **起動時に落とす**。これは運用者が見るべきものなので。

### fork を既定で無効にする理由

fork からのプルリクエストは、コミット権を持たない人が開ける。
そこに資格情報を持つサーバーを差し出す既定値は、
`docs/security.md` が書いている方針と矛盾する。
実装した直後に自分で見つけた穴で、PR #22 のブランチに追加で入れてある。

### 検証について

生成した config を**実物の opencode に食わせ**、受理されプレースホルダが解決されることを確認した。
検証に使われる MCP スキーマは、記憶ではなく**そのバイナリから読み出した**。

## 影響

- `McpLocalConfig` は `{type, command, cwd?, environment?, enabled?, timeout?}`、
  `McpRemoteConfig` は `{type, url, enabled?, headers?, oauth?, timeout?}`。
  `MCPServer.Validate()` がこれに合わせて検証する。
- `AllowFork` は kibitz 側の概念なので、**config を書き出す前に落とす**。
- kibitz 自身のツールサーバー (`kibitz-mcp`) はこの三層の外にあり、常に有効
  (ADR-0016)。資格情報を持たないので、同じ扱いにする理由がない。
