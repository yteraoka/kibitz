# ボットが動く条件を狭くする

- **状態**: 採用 (2026-09-21)
- **関連**: `77a529c` / `00aa871` / `52b6d94` / `docs/configuration.md`

## 背景

ボットは、呼ばれていないのに動くと嫌われる。
そして**呼ばれていないのに動く経路**は、素朴に実装すると驚くほど多い。

実際に踏んだものを挙げる。

- プルリクエストのテンプレートに「`/kibitz review` と書くとレビューされます」
  と説明を書いたら、**そのテンプレートでレビューが走った**。
- 誰かのコメントを引用返信すると、`> /kibitz review` の `> ` が剥がされて**引用に従った**。
- 既定のメンションが `@kibitz` だったが、**`github.com/kibitz` は実在の人**である。
  公開リポジトリでレビューを依頼するたび、その人にメールが飛んでいた。
  しかも kibitz 自身はその経路では届かない (GitHub App にメンションできるアカウントは無く、
  コメントのことは webhook で知る)。**`@` は何も買わないまま、見知らぬ人の受信箱を代償にしていた。**
- プルリクエストのイベントが、誰も望んでいなくても全部キューに載っていた。

## 決定

**ボットが動く条件を、意図が明確な場合だけに狭める。**

- **コマンドはコメントの先頭にあるときだけコマンド**。
  `ParseCommand` は**1 行目だけ**、その**最初の単語だけ**を読む。
- **コードは発話ではない。** フェンスブロックとインラインコードを
  照合の前に空白で潰す。メンション・コマンド・トリガーキーワードのすべてに対して。
  `StripCode` は**行数を保つ**。先頭行ルールは位置で決まるので、
  1 行目が丸ごとコードのコメントには「コマンドが無い」のであって、
  2 行目が繰り上がってはいけない。閉じていないバッククォートはバッククォートであって、
  残り全部を飲み込むスパンではない。
- **既定のメンションは `/kibitz`**。forge が解釈しないトークンにする。
- **キーワードによるゲート** (`KIBITZ_TRIGGER_KEYWORDS`)。
  タイトルまたは本文にキーワードがあるプルリクエストイベントだけを載せる。
  メンションもキーワードの 1 つとして数えるので「`/kibitz` お願いします」で通る。
  **コメントとコマンドはゲートしない** — ボットに話しかけている時点で依頼である。
  空にすれば従来どおり全部レビューする。
- 弾いた配信は **204 と理由** (`reason=no_keyword`) で答える。

## 理由

**間違えたときのコストが非対称**である。

- コマンドとして解釈しすぎると、**勝手に動く**。これはボットを止められる種類の驚きである。
- コマンドとして解釈しなすぎると、**もう一度書けばよい**。

だから境界は「解釈しない」側に倒す。

ただし**メンションで呼びかけるのは、下のほうでも届く**ようにしてある。
ただし質問として。回答経路は変えていないので、
**間違えたときのコストが「行動」ではなく「返事」になる**。

引用返信が効かなくなるのは、古いルールが**逆に**扱っていた場合そのものである。
`> ` を剥がして引用に従っていた。

## 影響

- ヘルプ文は `@kibitz` がハードコードされていたが、トークンは設定可能だった。
  `/kibitz` で動くデプロイが、無視する文字列を書けと案内していた。
  ワーカーもサーバーと同じく `KIBITZ_MENTION` を読み、
  **ヘルプにはコマンドをどこに書くべきかも書く**ようになった。
- 既存のデプロイは、新しい語を利用者に伝える必要がある。
  名前を所有している人のために、`KIBITZ_MENTION` は `@` 形式も受け付ける。
- ドラフトの扱いは**サーバーではなくワーカーが決める**。
  `.kibitz.yaml` を読めるのはワーカー側だけなので。
- **リプレイ窓は既定で無効**。5 分にしたら、失敗した hook の Redeliver が
  黙って 204 を返した。payload は署名で認証済みであり、
  本当の重複排除は delivery id の照合 (ADR-0006) である。
