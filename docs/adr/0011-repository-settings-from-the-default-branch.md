# リポジトリ設定はデフォルトブランチから読み、一方向にだけ効かせる

- **状態**: 採用 (2026-09-22)
- **関連**: PR #19 / PR #20 / PR #25 / `docs/configuration.md`

## 背景

リポジトリごとにレビューの挙動を変えたい。
対象から外すパス、重点を置く観点、コメント数の上限、使うモデル。
これを**誰が、どこに書けるか**が問題になる。

`.kibitz.yaml` をリポジトリに置く形は自然だが、素朴にやると 2 つの穴が開く。

- プルリクエストのブランチに `.kibitz.yaml` を置けば、
  **そのプルリクエストのレビューのされ方を、そのプルリクエストが決められる**。
- 設定キーを何でも受け付けると、
  **コミット権を持つ人がデプロイの設定に手を伸ばせる**。
  コミットできる人の集合と、kibitz をデプロイする人の集合は同じではない。

## 決定

**`.kibitz.yaml` をデフォルトブランチからのみ読み、一部のキーは一方向にしか効かせない。**

- GitHub は contents API を ref 指定なし、GitLab は files API を `ref=HEAD` で読む。
  どちらも**デフォルトブランチ**を指す。
- **`repoconfig.Config` にあるキーだけが効く。** 未知のキーは無視ではなく、
  「これは実装されていない」と名指しでサマリに書く。
- **一方向のキー**:
  - `guidelines` はデプロイ側の方針に**追記**される。置き換えではない。
  - `max_comments` は**下げる方向にしか効かない**。
- `paths_ignore` は**プロンプトだけでなく差分そのもの**をフィルタする。
- **設定の問題でジョブを落とさない。** 読めない・パースできない場合は
  デプロイ側の設定にフォールバックし、サマリコメントにそう書く。

## 理由

### デフォルトブランチから読む理由

ADR-0010 の原則そのままである。
設定は**指示の位置**に入る (何をレビューするか、何を無視するかを決める) ので、
囲いは効かない。だから出どころで守る。
デフォルトブランチはコミット権を持つ人が管理しているブランチである。

### 一方向にした 2 つのキーの理由

**`guidelines` が追記なのは**、デプロイ側が落とされたくないルールこそが、
落とされるルールだからである。
「秘密情報をコメントに書くな」を上書きで消せる設定は、設定ではなく穴。

**`max_comments` が下げる方向にしかきかないのは**、
1 つのプルリクエストがコメントで埋まらないようにするのは
デプロイ側の判断だからである。リポジトリが増やせるなら上限ではない。

### 未知のキーを黙って無視しない理由

`.kibitz.yaml` に `budget:` と書いた人は、予算が効いていると思っている。
黙って無視すると、**効いていないことに気づく方法が無い**。
だから「`mcp`、`budget`、`implement`、`allow_verdict`、`answer.mention` は
計画されているが未実装」と名指しする。

`answer.mention` は**実装できない**ので、そう書いてある。
メンションの照合は publish 前のサーバー側で行われ、そこでは `.kibitz.yaml` を読まない。
リポジトリ単位のメンションは、イベントをキューに載せない結果になってしまう。

### 設定のタイポでジョブを落とさない理由

**設定ファイルのタイポで止まるレビューは、全員の設定で走るレビューより悪い結果**である。
1 人のミスで、そのリポジトリのレビューが全部止まる理由がない。

### `paths_ignore` が差分自体を削る理由

プロンプトからだけ消すと、**エージェントが他の手段でそのファイルを読んだ場合**に
コメントできてしまう。差分から消せば、
指摘の位置検証が同じファイル集合に対して行われるので、投稿されない。

## 影響

- 実際に効くキー: `review.enabled` / `triggers` / `skip_draft` / `paths_ignore` /
  `focus` / `language` / `min_severity` / `max_comments` / `model` /
  `answer.enabled` / `guidelines` / `mcp.allow` (ADR-0015)。
- YAML ライブラリは **`goccy/go-yaml`**。`go-yaml/yaml` はアーカイブされている。
- PR #20 で 2 つの不具合を直した。いずれも kibitz 自身のレビューが見つけたもの。
  - **`max_comments: 0` が上限を上げていた。** `<= 0` を「未設定」と解釈していたため、
    0 を書くと 0 ではなく「デプロイ側の値」になっていた。
    再現したところ、上限 5 のデプロイで 10 件投稿された。
    いまは 0 は 0 で、「未設定」は 1 か所で解決する。
  - **`vendor/` がどのパスにも一致しなかった。** 末尾の `/` を落とし、
    ディレクトリパターンに `(?:/.*)?` を付けて配下も含むようにした。
- 規約ファイル (`AGENTS.md` / `.kibitz/guidelines.md`) も同じ理由で
  デフォルトブランチから読む。`KIBITZ_REPO_GUIDELINE_FILES` で変更でき、
  `off` で無効化できる。順序はデプロイ側の方針 → 規約ファイル → `.kibitz.yaml` の追記。
